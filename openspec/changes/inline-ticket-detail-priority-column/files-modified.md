## Debugging note (systematic-debugging.md)

While writing the new `watch-smoke.test.sh` "P actually reorders the tickets pane" case:

- **Root cause:** the smoke-test's own ordering check picked up the inline detail pane's header line (which also renders the selected ticket's identifier, with no `[ ]` checkbox prefix) as the "last occurrence" of an identifier, rather than the tickets-pane row — a test-script bug, not a product bug.
- **Probe:** captured a single real run's raw output (`node bin/concertino watch --out=... > /tmp/lp3out.txt`) and inspected it with `cat -A | grep -n CON-4`; confirmed the tickets-pane rows (lines 49-50) were already in the correct post-`P` order (CON-42 before CON-41), while a later, unrelated detail-pane header line (line 54, `CON-42  urgent-priority-ticket`, no checkbox) was what `grep -n 'CON-42' | tail -1` was actually matching.
- **Fix:** scoped the smoke test's grep to `\[ \].*CON-4[12]` (the checkbox-prefixed row only). Re-ran `test/scripts/watch-smoke.test.sh`: all 54 cases pass, including the new one.
