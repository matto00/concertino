# CON-25: Fast-forward local main after every run, and escalate to the TUI when it can't

## Description

Nothing in the workflow brings the local checkout forward after a PR merges. Every merge — by a human, by another run, by anyone on the team — leaves local `main` behind `origin/main`, silently. This is long-standing, months old, not a symptom of this project's pace.

The normal workflow never touches `main` directly, so a **fast-forward is almost always the correct and safe action**. It should just happen, as part of cleanup, after every run.

### Three distinct ways the staleness bites

**1. Sibling runs conflict.** `setup-worktree.sh` deliberately cuts new branches from the *fetched remote* base, which is right — it stops a burst of sequential tickets branching from a local base that has fallen behind. But a run started while a sibling's PR is still open branches from a base without it. That produced a real conflict here: CON-8's PR had to be rescued after CON-7 merged first, because both touched the same emission code.

**2. The rendered artifacts go stale.** The expensive one. Rendered agents under `.claude/agents/` are gitignored, so they never travel through git — they are regenerated by `concertino sync` from the local `core/`. If local `core/` is behind, a sync renders *yesterday's* agents. That cost an hour early in this project: every run emitted no telemetry and nothing said why. The `doctor` drift check exists because of it; CON-13 exists because a related resolution bug made it worse.

**3. A stale base is invisible.** The dashboard shows runs, gates and verdicts, but nothing about whether the repository those runs branch from is current.

### The shape

**Fast-forward by default, escalate when you can't.** Phase 4 cleanup is the natural home — it is the one moment the workflow knows a merge happened.

When the fast-forward is not clean, the resolution is usually mundane — stash, fast-forward, unstash — but it is a judgement call about someone's uncommitted work, so it must not be taken unilaterally. Escalate instead.

### The escalation needs to be visible everywhere

This is a **top-level concern**, not a property of one run. If the base cannot move forward, every subsequent run branches from a stale base — so it must be visible regardless of which screen you are on, not buried in one run's row.

Requirement: a persistent notice across **all** screens, e.g. `CON-15: agent can't fast-forward main`, with an input box to reply to the agent holding it.

That is a new capability. Today's escalation screen is per-run and reached from the fleet view; this is a global banner plus a reply path. Worth building as a **general cross-screen escalation layer** rather than a one-off for git — any blocking escalation would benefit from being visible from wherever you happen to be, and the machinery already exists on the answering side (`answer.json`, `emit-event.sh --await`, the `[t] type a reply` flow).

## Acceptance criteria

* Local `main` is fast-forwarded as part of Phase 4 cleanup, without a human running git by hand.
* A clean fast-forward proceeds silently. Anything else — dirty tree, diverged base, conflict — escalates and changes nothing.
* **Never** fast-forward over uncommitted work or a diverged base. Losing local changes to a hygiene step would be far worse than the staleness it fixes.
* The escalation appears on every screen with an input box to reply, and clears when resolved.
* After a successful fast-forward, either re-render or state clearly that a re-render is needed, so the rendered-artifact staleness in (2) cannot recur silently.
* `doctor` reports when local `main` is behind its remote — it already detects the *consequence* (artifact drift) and should name the usual cause.
* Safe with several worktrees live, since the main checkout and every run's worktree share one object store.

## Notes

This matters more once CON-24 (agent-merge: let a verified run merge its own PR) lands. Agent-merge makes merges more frequent and less observed, so the window in which a base is stale gets both wider and less noticed.
