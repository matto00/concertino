## Standing Constraints

- [C1] A text-matching probe over ticket/description prose must carry a POSITIVE control proving the needle matches the real-world markdown rendering (e.g. a backticked `origin_kind`: key) before any zero-hit result is reported as evidence. A negative control alone is insufficient — this change's own Planning shipped a false-negative zero on exactly that omission.
- [C2] Never read ticket descriptions or state via `fetchOneTicket`/`ISSUE_QUERY` — it selects only `id`/`identifier`/`labels` and returns an empty description. Description- and state-bearing reads go through `fetchTickets` with explicit `stateTypes`.
- [C4] The recovered tier means strictly what the provenance tier missed: dedupe by ticket id and disclose the excluded count. The filing convention writes provenance markers into every filed ticket's description unconditionally, so the tiers overlap unless explicitly made disjoint.
- [C3] Never render a survival percentage over a denominator below the stated minimum (default 5); print the counts and a small-sample marker instead. Applies per segment and per period, not only to the overall figure.
- [C5] An explanatory annotation must be guarded on the VALUE actually observed, never on a condition that merely correlates with it. Rendering a cause ("the template hardcodes X") above data showing not-X is a false claim, not an imprecision — name the observed value instead.
- [C6] Name a failure shape for its MECHANISM, never for an incidental trigger observed in one demonstration. A mischaracterised shape is as much a defect as an overstated rule.
- [C7] When a count changes, audit EVERY reference to it — body prose as well as headings, and in every artifact that restates it. Checking only headings is a narrower subject than the claim being licensed.
