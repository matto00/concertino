## Source

- `lib/ui/queue.js` — new `forceStart(queue, ticket)` export: moves one specific pending ticket straight to `inFlight`, bypassing `tick()`'s `maxConcurrent` admission gate. Shaped exactly like `tick()`'s own return value (same `toLaunch`/`queue` shape, `launchCommand`/`restoredFrom` passthrough) with one deliberate difference: `confirmed` is carried through unchanged from the input queue rather than hard-coded to `true` (design.md Decision 4 — required by the design-soundness skeptic gate), so force-starting one ticket out of a CON-29-restored, not-yet-confirmed queue never silently reactivates auto-admission for the rest of that batch.
- `lib/ui/screens/launchplan.js` — new `parseLaunchCommand(launchCommand)` export: the read-side counterpart to the existing `withAgentMergeFlag`/`withSpeedFlag`, parsing a batch's speed/agent-merge setting back out of a `launchCommand` string against the same token format/position. Used by `fleet.js`'s QUEUED row rendering rather than duplicating a second regex there.
- `lib/ui/screens/fleet.js`:
  - `renderQueuedRow` now takes an `opts` object (`focused`, `speed`, `agentMerge`) and renders a `»` marker on the QUEUED-locally-focused row plus the batch's speed/agent-merge fields (agent-merge omitted when `null`).
  - `renderFleet` parses `queueState.launchCommand` once per render (not per row) via `launchplan.parseLaunchCommand`, and threads `focus`/`queueFocus` through to the QUEUED row loop.
  - `buildHeadTail` gains a `forceStartConfirm` branch (checked before `quitConfirm`) rendering the load-bearing overage warning, and the ordinary footer hint line now advertises `1-9 jump` (always) and `f force-start` (only when a QUEUED section is present this frame).
  - New `sectionJumpTargets(runs, queueState)` helper: the ordered, positionally-numbered list of sections actually rendered this frame (reusing `buildSections`/`bucketRuns`), used by digit-key resolution.
  - `handleKey` gains: digit-key (`1`-`9`) section jump (`jump` for runs-backed sections, `focus-queue` for QUEUED); a `focus === 'queue'` branch reinterpreting `j`/`k`/arrow-aliases (`move-queue-focus`), `f` (`open-force-start-confirm`), bare Escape (`exit-queue-focus`), and suppressing `Enter`/`l`/`n`/`N`; and a `forceStartConfirm` interception checked *before* `quitConfirm` (`y` → `confirm-force-start`, anything else → `cancel-force-start`).
  - `render()` threads `focus`/`queueFocus`/`forceStartConfirm` from state into `renderFleet`'s opts.
- `lib/ui/watch.js`:
  - New state: `focus` (`'runs'|'queue'`, default `'runs'`), `queueFocus` (default `null`), `forceStartConfirm` (default `null`) — added to `currentState()` and re-clamped every `draw()` (mirroring the existing `scrollOffset` re-clamp) so a queue that shrinks/empties never leaves a stale QUEUED-local cursor on screen.
  - New `scrollToShow(targetSelected)` helper factored out of the `'move'` case's scroll-into-view logic, shared by the new `'jump'` action.
  - `applyAction` gains cases: `jump` (absolute-target counterpart to `move`, also resets focus to `'runs'`), `focus-queue`, `move-queue-focus`, `exit-queue-focus`, `open-force-start-confirm`, `cancel-force-start`, `confirm-force-start` (calls `queue.forceStart`, `submitTicket`, updates `queueState`, and persists via the existing `queue-cache.js` write path — mirroring the existing `tick()`-driven launch path).

## Tests

- `test/queue.test.js` — unit tests for `forceStart`: pending→inFlight move, no double-admission by a subsequent `tick()`, correct `maxConcurrent` accounting once force-started, no-op on a ticket not in `pending` (including a stale/already-inFlight reference), `confirmed` passthrough for both `false`→`false` and `true`→`true`, and `launchCommand`/`restoredFrom` passthrough.
- `test/launchplan.test.js` — unit tests for `parseLaunchCommand` across every token combination (both flags, speed-only, agent-merge-only, bare `{{TICKET}}`, no-placeholder custom override, null/undefined/empty input), plus a round-trip check against `withAgentMergeFlag`/`withSpeedFlag`.
- `test/fleet.test.js` — unit tests for digit-key section jump (positional numbering, empty-section skipping, out-of-range no-op, QUEUED participation/re-resolution), the QUEUED-local focus cursor's `handleKey` behavior (j/k/arrows, Escape, Enter/l/n/N suppression, q/Ctrl-C passthrough, `f`), the force-start confirmation gate (`y`/anything-else, checked-before-`quitConfirm` ordering), the confirmation's rendered warning text, the QUEUED-local focus marker, and QUEUED rows showing speed/agent-merge (including omission when absent, and shared-per-batch consistency).
- `test/watch.test.js` — three end-to-end integration tests wired through the real poll loop and a faked tmux session: (1) a digit press jumping directly to a scrolled-past section and scrolling it into view; (2) a full QUEUED-focus round trip (digit-jump in, move the cursor, Escape out) leaving the run selection completely unchanged; (3) a force-start confirm/cancel/confirm cycle against a real `maxConcurrent: 1` restored queue, asserting no spawn on cancel, exactly one spawn on confirm, and the persisted `.concertino/cache/queue.json` record moving the ticket from `pending` to `inFlight`.
