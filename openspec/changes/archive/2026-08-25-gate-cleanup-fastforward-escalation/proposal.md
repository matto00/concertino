## Why

`core/scripts/cleanup.sh`'s fast-forward escalation (`core/scripts/cleanup.sh:345`) calls
`emit-event.sh escalation --await` unconditionally whenever the local base branch can't be
fast-forwarded cleanly (dirty tree, diverged base, or an unexpected failure). CON-126 introduced
`tui-attached.sh` and gated the orchestrator's own escalation-raise procedure on it, but never
touched this script-level call site — so on a no-TUI run (a plain `/concertino-deliver` session,
cron, or CI) `cleanup.sh --phase4` still blocks for the full `dashboard.escalationTimeoutMinutes`
window (default 8 minutes) at the very end of a run, after everything else is already merged,
against a dashboard nobody is watching. This is routine in the helio checkout because
permanently-untracked working files make the base tree read as dirty on almost every run.

## What Changes

- `core/scripts/cleanup.sh`'s fast-forward escalation block consults `tui-attached.sh` before
  calling `emit-event.sh escalation --await`.
- With no TUI attached, the block skips the blocking `--await` call entirely and defaults straight
  to the documented timeout behavior (`skip` — leave the base exactly as found), since a shell
  script has no chat channel to fall back to the way the orchestrator does.
- The no-TUI outcome is reported via the same `gate.warning` telemetry event the script already
  emits for an unresolved retry outcome (`gate=phase:cleanup`, `resolved=false`, a `reason=`
  distinguishing "skipped, no TUI attached" from the existing "still behind after retry"/"unknown
  after retry" reasons) — never silently swallowed by `|| true`.
- With a TUI attached, behavior is completely unchanged: `--await` still blocks, `retry` still
  re-runs the algorithm exactly once, any other answer (or a timeout) is still treated as `skip`
  and does not raise a second escalation.
- A timeout is never treated as an approval or a retry, on either branch — unchanged from today.

## Capabilities

### New Capabilities

(none)

### Modified Capabilities

- `main-fast-forward`: the "An unresolvable fast-forward escalates with a bounded retry/skip loop"
  requirement now additionally requires consulting `tui-attached.sh` before calling
  `emit-event.sh escalation --await`, and defines the no-TUI behavior (skip immediately, emit
  `gate.warning` reporting the skip) as part of that same requirement.

## Impact

- `core/scripts/cleanup.sh` (source of truth; `scripts/concertino/cleanup.sh` is a rendered copy
  regenerated by `concertino sync` and is not edited directly).
- `openspec/specs/main-fast-forward/spec.md` (delta for the modified requirement).
- No schema, API, or client/server contract changes. No new script dependency — `tui-attached.sh`
  already exists (CON-126) and is already invoked by the orchestrator's own procedure; this reuses
  it, adding no new liveness-detection mechanism.
- `core/roles/orchestrator.md:1060-1067` documents `cleanup.sh`'s escalation as unconditionally
  blocking; after this change that's only true on the TUI-attached path. This change deliberately
  does NOT edit that file — it is out of scope, owned by a concurrently-live sibling run (CON-130)
  in this same repo — see design.md Decision 5 for the full rationale and the standalone
  follow-up-ticket plan.
