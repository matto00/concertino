### Change Requests

1. **spec.md still mandates the lease release Decision 4a withdrew.** `specs/verdict-sha-binding/spec.md`, scenario "Stale outcome releases the auditor lease", requires "the auditor lease acquired earlier in the same invocation is released before exit". Decision 4a says the opposite, and the spec is the normative artifact the archive step syncs. Delete/replace that scenario (state instead that the lease is released by the auditor's own verdict, per CON-171's unchanged protocol). While there, add scenarios for the behaviour the revision introduced and the spec does not cover: the base-scoped branch-contribution comparison (a base-derived change to an untouched path passes; to a touched path refuses), the archive-prefix being a caller-supplied parameter, the head-being-merged assertion, and Decision 6's override asymmetry.

2. **proposal.md contradicts the revised design in two places.** "releases the auditor lease on the way out because the run is leaving auditor territory" (contradicts Decision 4a, and repeats the symmetry claim round 1 refuted) and "`core/roles/evaluator.md`, `core/roles/skeptic.md`, `core/roles/orchestrator.md` and their rendered agent definitions" / Impact's same phrase (contradicts task 5.2, which I verified is correct — no agent renders are tracked here). Fix both.

3. **Decision 1's `<base_ref>` is undefined, can be unset, and can be stale — CR-1's false refusal partially survives.** Three concrete problems the design must settle, not the executor:
   (a) *Unset.* `BASE_REF` is assigned only inside the `if [ $? -eq 0 ]` guard on `:182`'s `gh pr view`. When that call fails, `BASE_REF` is unbound and the script runs under `set -u` (`:2`) — condition 3 would abort with an unbound-variable error, after the lease acquire, with no `STALE` message. Specify the resolution (`.baseRefName` → `CONCERTINO_BASE_BRANCH` → `main`) at a scope condition 3 can see, and specify that failure to resolve it refuses per Decision 3.
   (b) *Which ref.* `<base_ref>` must be `origin/<base>` (the worktree has no local `<base>` branch checked out) and it must be an **ancestor of `<head>`** for step 1 to mean what Decision 1 claims. State that, and state what happens when it is not (refuse).
   (c) *Staleness.* `git fetch origin "$BASE_REF"` runs **only** on the BEHIND path. Both consuming repos run many worktrees off one clone with a **shared** `origin/<base>` ref that sibling lanes advance. If `origin/<base>` has moved past the commit this branch merged, `MB_H = git merge-base origin/<base> <head>` is the older common ancestor, so `git diff --name-only MB_H <head>` re-admits every base-derived path merged into the branch into `PATHS` — and those paths differ between `<reviewed_sha>` and `<head>`, so the check refuses. That is round-1 CR 1's failure mode, reintroduced through the very step meant to close it, and it is *more* likely the busier the fleet. Decide the freshness contract (e.g. fetch the base before computing merge-bases, or derive `MB_H` from the branch's own first-parent history rather than a mutable remote ref) and add a self-test that advances `origin/<base>` beyond the merge the branch performed and asserts PASS.

4. **Empty `PATHS` silently inverts the pathspec.** Step 3 is specified as `git diff --name-only R H -- <PATHS minus the archive prefix>`. When `PATHS` is empty, the command degenerates to `git diff --name-only R H -- ':(exclude)<prefix>/*'`, which is not "no paths" but **"every path except the prefix"** — a whole-commit diff, i.e. exactly the comparison Decision 1 rejects, and a mass false refusal on any base-reconciled run. (Reachable whenever step 2's union comes back empty, including on the git-failure legs if their exit status is checked but the empty output is still used.) Specify the guard explicitly in design.md and tasks.md — empty `PATHS` means the branch contributed nothing outside the prefix and the leg passes, or it refuses, but it must be decided and it must be self-tested (task 4.x), not left to the shape of a shell array.

5. **Decision 5's premise is factually wrong: `headRefOid` is not fetched anywhere.** `grep -c headRefOid core/scripts/check-merge-readiness.sh` = 0; the three `gh pr view` calls request `mergeStateStatus,baseRefName`, `statusCheckRollup`, and `mergeable,mergeStateStatus,reviewDecision`. Task 2.3's parenthetical "(already fetched by this script)" will lead the executor to look for a value that does not exist. Correct the claim and specify: which call gains `headRefOid`; that it must be queried **after** condition 0's reconcile-and-push (a value from `:182` is pre-push and would mismatch local HEAD on every reconciled run — a false refusal on the healthy path); that an unavailable/failed query refuses per Decision 3; and how the known GitHub read-after-push lag is handled (re-query, or classify this refusal as exit 1 rather than exit 4 so it is not silently churning re-reviews).

6. **Task 4.6's "EVERY new assertion goes RED against the pre-fix script" is unsatisfiable for the must-PASS assertions, which are the ones most at risk of being vacuous.** Tasks 4.2 (healthy squash-shaped case PASSes), 4.3's first half (base-derived untouched paths PASS) and Decision 6's evaluator-leg-passes case assert `PASS`; the pre-fix script passes unconditionally, so they are green before AND after — precondition-guaranteed by construction, the CON-170 shape. Worse, each is also green if the fixture never reaches condition 3 at all (missing log, failed `gh`), so a broken fixture reads as a proof. An unsatisfiable rule invites the executor to fudge the transcript or weaken the assertion. Restate: negative-control assertions are proven by **mutation of the fix** (e.g. drop the `':(exclude)<prefix>/*'` term → 4.2 must go red; drop the `PATHS` restriction → 4.3 must go red; force empty `PATHS` → CR 4's case must go red), and each must additionally assert it reached condition 3 (e.g. by asserting the exact PASS output, not just rc 0). Only the refusal assertions (4.1, 4.3 second half, 4.4, 4.5-refuse, and the emit-side `head_sha_source`/inference/absent legs) are provable by red-against-pre-fix.
