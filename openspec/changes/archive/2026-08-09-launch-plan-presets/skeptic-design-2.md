### Change Requests

1. **`specs/launch-presets/spec.md` — the provider-apply Requirement and its "unreachable dimension" Scenario still omit the `perRowEditable` guard, which is the exact gap round 1's CR2 named for this file and which was not addressed.**
   Round 1 required this fix in *two* places — Decision 3 (done) and this spec.md text (not done). As written, an implementer working from spec.md alone (the durable, archived capability description — the artifact most likely to be consulted after this change ships and design.md/tasks.md are gone) would build `w`'s provider-apply condition as `providerConfigured && reachable`, silently missing the `perRowEditable` half `cycle-provider` already enforces — reintroducing exactly the inconsistency ("`w` sets a value the batch's own `p` key would itself refuse to set," design.md line 67) CR2 existed to close. Required revision:
   - Update the Requirement text at `specs/launch-presets/spec.md:71` from "...`provider` (only when a provider is configured for the project and the preset's provider value is reachable from the resulting harness)..." to include the `perRowEditable`/no-`launchCommand`-override condition (mirroring design.md Decision 3's now-correct wording).
   - Update the "An unreachable dimension is left unchanged, not errored" Scenario (`specs/launch-presets/spec.md:77-79`) to also cover the case where the project runs under a `dashboard.launchCommand` override (`perRowEditable` false), not just "a provider not configured for the project."
