### Verdict: REFUTE

### Change Requests
1. **spec.md self-contradiction — the normative Delivery gate still mandates red/green evidence.** `specs/.../spec.md`, requirement "Delivery blocks on missing gate-chain evidence", second bullet: "a persisted isolation-test evidence file (written by `test-gate-in-isolation.sh`) demonstrating a **red run and a green run** against a throwaway fixture repo under a hook-shaped environment." This is the exact requirement round 1 REFUTE'd, and it directly contradicts the same file's "Isolation-test helper" requirement and design.md Decision 5. An implementer building task 2.1 from the spec will require red/green markers the helper never emits, making passing evidence unobtainable. Rewrite this bullet to require a persisted transcript recording a **pass verdict** from the helper's single hook-shaped run.

2. **design.md's final Risks bullet still describes the deleted two-run model, and names a different selftest file.** It reads "proves the helper against a *known-bad* target ... and asserts the **red run** actually observes bareness ... and against a *known-good* target (**a script using the hardened `git_child` wrapper**) ... asserts the **green run** observes no corruption", and calls the selftest `test-gate-in-isolation.selftest.sh` — whereas Decision 5 and task 3.2 call it `test/scripts/test-gate-in-isolation.test.sh`. Update the bullet to the bundled known-bad/known-good *reference scripts* model and to one consistent selftest filename.

3. **The evidence lookup path is stated in a form that will not match what `persist-evidence.sh` writes.** spec.md and task 2.1 say the check looks for "a persisted `design.md` ... under `.concertino/runs/<TICKET_ID>/evidence/`". Per `core/scripts/persist-evidence.sh`'s header contract, the destination "preserves SOURCE_PATH's path relative to the top-level of the git working tree", so the real artifact lands at `.concertino/runs/<TICKET_ID>/evidence/openspec/changes/<CHANGE_NAME>/design.md`. A literal implementation of the spec text checks a path that never exists → the gate fails-closed on every gate-chain change, including compliant ones. Specify the actual nested destination (or an explicit change-name-agnostic discovery rule, e.g. locate `evidence/**/design.md`) in both spec.md and design.md Decision 3.

4. **The Delivery gate does not tie isolation evidence to the scripts actually changed — a compliant-looking run can bypass the ticket's third acceptance criterion.** spec.md requires only "a persisted isolation-test evidence file" / task 2.1 "at least one persisted isolation-test evidence file". Nothing binds that evidence to the gate script the diff added or modified: running `test-gate-in-isolation.sh` against any trivially safe unrelated script produces a passing transcript that satisfies the gate while the new hazardous gate is never exercised — precisely the incident this ticket exists to prevent, now passing a green gate. The helper already records the target script path in its transcript (Decision 5 step 5), so close this: require that, for each changed/added path in the diff that is a hook-invoked script, there is a persisted transcript whose recorded target path matches it, with a pass verdict. Also specify what is required for the case with **no** new/changed script (a `.husky/pre-commit` reorder or a gate deletion) — today spec.md unconditionally demands isolation evidence for any gate-chain diff, with no target to run it against, which is both ambiguous and unimplementable as written.

5. **"Fails loudly if the run touched anything outside its own `mktemp -d` fixture" has no specified mechanism and is not implementable as literally worded.** design.md Decision 5 step 6 and spec.md's fourth Isolation-test scenario ("every file the run touches is verified to be under the fixture's own `mktemp -d` path") require whole-filesystem write tracing, which nothing in `scripts/concertino/` can do portably. As written this will be silently downgraded during Execution to "the fixture looks fine" — the exact silent-downgrade the ticket's orchestrator notes forbid. Either specify the concrete, bounded mechanism (e.g. run with `HOME`/`TMPDIR` redirected into the fixture plus a pre/post snapshot of an enumerated set of at-risk paths: the real repo's `.git`, the worktree, the main checkout) and narrow the spec scenario's wording to what that mechanism can actually assert, or state explicitly that it is best-effort with the named limitation.

### Non-blocking notes
- The selftest split (methodology proven against bundled known-bad/known-good references; per-ticket run only produces one honest verdict on the real target) is sound and is **not** the circular self-check the ticket warns about — the known-bad reference couples the assertion to observed fixture state (`git rev-parse --is-bare-repository` flipping), not to a reimplementation of the helper's logic. I probed this specifically and found no circularity.
- Decision 7's stated reasoning for leaving commit-staging advisory (squash-before-delivery makes commit count unobservable at gate time) is verified correct against `core/roles/orchestrator.md` Phase 3 step 1, and satisfies the ticket's "state it explicitly, don't silently downgrade" instruction.
- `assert-phase.sh delivery`'s `TICKET_ID` is optional (`${4:-}` with a worktree-basename fallback); the orchestrator always passes it, so this is fine today, but the new check should fail-closed rather than skip if it is ever empty.
