## Context

`core/roles/orchestrator.md`'s "Harness resume model" section (lines ~38-100) already opens with a bolded rule: **"Never end your turn while a sub-agent you spawned or resumed is still outstanding."** It is restated at lines 96 and at every Phase 1/2 spawn/resume site. So the failure that produced HEL-671, HEL-630, and HEL-651 is not an absent rule — it is a rule that coexists, two sentences later, with: *"As the top-level `/concertino-deliver` session, waiting costs nothing: your session persists and will receive the sub-agent's result whenever it arrives, however long that takes."* All three failing runs were top-level sessions. That sentence does two things at once: it implies an arriving signal ("will receive... whenever it arrives" — exactly the language the ticket's "Root cause to confirm" section asks us to check for and correct), and it tells the top-level orchestrator that ending its turn to wait is *costless*, which reads as permission for precisely the observed behavior. A fourth restatement of the prohibition, added without touching this sentence, would sit inside the same document as its own contradiction and is not expected to succeed where three prior restatements (CON-76, CON-127, CON-134) already failed.

## Goals / Non-Goals

**Goals:**
- Remove the internal contradiction: rewrite the "waiting costs nothing... whenever it arrives" sentence so "free" describes session *persistence* across a blocking call (the harness resumes this same session when the call returns — a fact about the runtime, not a license), never a reason to end the turn while the call is still outstanding.
- Add one closed enumeration of legitimate turn-ending conditions, placed directly beside the corrected sentence (not in a separate, disconnected subsection), contrasted against the "ending a turn merely to report progress" anti-pattern.
- Broaden the audit beyond the ticket's own suggested grep terms to the terms that actually appear in the contradiction found here, and sweep `core/roles/orchestrator.md` (the source) end-to-end.
- Produce a real demonstration, owned by the orchestrator (the role whose behavior is in question — an executor cannot demonstrate orchestrator turn discipline), where sub-agent terminal state is established from artifacts alone, with the observations (path, commit SHA, timestamp) recorded in this run's own delivery notes.
- Require executor/evaluator reports to carry an explicit "what was / was not verified" section as a fixed target for the final-gate skeptic.

**Non-Goals:**
- A mechanical phase-script assertion that fails if the orchestrator yields mid-flight. No harness hook exists for a stateless script to observe "the orchestrator's turn ended" — this requires an external, heuristic `events.jsonl` watchdog, filed as CON-141 and explicitly out of scope here (confirmed via escalation).
- Codex/OpenCode adapter parity — CON-135's scope.
- Any change to `scripts/concertino/*` scripts.
- Adding a fifth/sixth restatement of the existing prohibition with no other change — rejected per the design-gate skeptic's finding that this is the same class of intervention that already failed three times.

## Decisions

**Fix the contradiction first, add the enumeration second.** Rewriting lines ~40-43 is the load-bearing change; the closed enumeration is secondary reinforcement placed immediately beside the correction so a reader encounters "here is what waiting-is-free actually means" and "here is the closed list of legitimate stops" as one continuous passage, not two independently-locatable facts (which is how the current bolded rule and its contradiction already coexist without conflict resolution).

**Rewritten framing:** "waiting costs nothing" is reframed to describe the fact that the *session itself* is not destroyed by a long-running blocking call (as opposed to a sub-agent role, whose session is destroyed if it returns control early) — never as permission to *end this turn* while that call is still in flight. The corrected text states explicitly: the call blocks; you do not get control back until it returns; there is no "wait" to end a turn on, because you are never holding control during the wait in the first place. This directly targets the reasoning error line 66-72 already names ("still waiting" on a call that hasn't returned is not a state you can choose to exit by ending your turn).

**Audit term list, revised:** `notif`, `report back`, `let me know`, `will send`, `wait for it to` (original ticket suggestion) plus, per the design-gate skeptic's finding: `wait`/`waiting` (bare stem, manually reviewed — high false-positive rate expected, e.g. legitimate uses like "wait for the artefact"), `whenever it arrives`, `will receive`, `costs nothing`, `free at the top level`, `persists`. **Audit target, revised in round 3: `core/roles/orchestrator.md` (the source file) AND every `{{block:...}}` template it interpolates for the Claude Code harness (`harnessResume`, `ticketProvider`, `specScaffold`, `specArtifacts`, `standaloneTicket`, `specArchive`, `agentMergePermissionCheck`, `hygiene`, per `lib/cli/render.js`'s `block()` function).** A source-file-only grep structurally cannot see block-interpolated text — this is exactly how the `harnessResume` block's independent copy of the offending sentence survived rounds 1 and 2 undetected. The rendered `.claude/agents/concertino-orchestrator.md` file (the post-render artifact) is also checked directly in task 3.3, as a second, independent confirmation that nothing block-sourced was missed.

**The `harnessResume` block's own correction (round 3).** `core/roles/orchestrator.md:101`'s `{{block:harnessResume}}` — the last line of the "Harness resume model" section — expands, for the Claude Code harness, to `lib/cli/render.js`'s `case 'harnessResume':` fallback `return` (after the `codex`/`opencode` early returns). That text independently states: "**Never end your turn while a spawned or resumed sub-agent is still outstanding.** As the top-level `/concertino-deliver` session, waiting is free — your session persists and receives the sub-agent's result whenever it arrives." — the same contradiction-producing construction as the text corrected in `core/roles/orchestrator.md` itself, ~60 lines earlier in the rendered document. This is corrected using the identical reframing decision above (persistence-across-a-blocking-call, not license), while preserving the block's own accurate, distinct content — the "the call's return value IS the authoritative result, there is no further report to wait for" explanation and the existing "poll for the artefact the sub-agent was told to produce (its report path, or a new commit on the branch)" fallback, both of which are correct as written and out of scope for this correction. Because both the source file's corrected passage and the block's corrected passage land in the same rendered section, the two are reconciled so the rendered document states the rule once, coherently — not the never-end-your-turn rule followed 60 lines later by a second, independently-worded restatement of the same rule. `adapters/codex/header.md`'s own "free at the top level" phrase (the Codex branch) is a separate, out-of-scope copy per CON-135.

**Compatibility check against the existing "explicit fallback" requirement.** `openspec/specs/orchestrator-turn-discipline/spec.md`'s "The role states an explicit fallback when the harness cannot wait inline" requirement (harness-can't-wait-inline -> poll or escalate) is unaffected by this change: it already prescribes polling/escalating rather than waiting, and does not use any of the corrected/removed language. No modification needed for that requirement — verified by re-reading it against the corrected framing.

**Demonstration ownership and shape:** the orchestrator delivering CON-140 itself performs the demonstration, since "did the orchestrator poll instead of wait" is not observable or performable by an executor. Concretely: at one spawn/resume point in this run's own Execution/Evaluation loop, before consuming the call's return value as the primary signal, the orchestrator additionally inspects the sub-agent's expected artifact directly (report file existence/path, `git log` on the worktree branch for a new commit, `workflow-state.md`) and records those concrete observations (file path, commit SHA, timestamp) in the delivery run's own notes — demonstrating the artifact-inspection path is real and exercised, not merely described.

## Risks / Trade-offs

[Risk] Rewriting "waiting costs nothing" risks losing the legitimate, accurate point it was trying to make (that a top-level session is not destroyed by a long blocking call, unlike a nested sub-agent session). → Mitigation: keep that accurate fact, stated without the "whenever it arrives" / license framing — see Decisions above.

[Risk] A doc change alone still cannot mechanically prove the behavior is fixed — model behavior is not deterministic. → Mitigation: this ticket's own delivery run is itself the demonstration, with concrete recorded observations (not just an assertion); the final skeptic gate REFUTEs any report that dresses up a doc diff as sufficient evidence without those observations present.

[Risk] The broadened audit's bare-stem terms (`wait`, `persists`) will have many legitimate hits (the doc correctly uses "wait" throughout to describe blocking calls). → Mitigation: audit is manual review of grep hits, not automated find/replace; only correct hits that actually imply an automatic signal or license early return.
