## Context

Concertino sub-agents (executor/evaluator/skeptic/auditor) are spawned via the `Agent` tool or resumed via `SendMessage`. A spawned subagent starts in "the main conversation's current working directory" — a FIXED baseline for the whole life of that agent's Bash tool (reproduced live, independently, by both design-gate skeptic rounds: a `cd` performed inside one Bash call does not survive to the next; every Bash call in a given role's session resets to the same starting ambient cwd).

**Two rounds of design-gate REFUTE established two hard constraints this revision must jointly satisfy, not trade off against each other:**
- **Round 1**: a check that only re-derives state from `WORKTREE_PATH` itself (e.g. `cd`s into it and checks what's there) is invariant under the actual ambient cwd, and therefore returns `READY` on the live incident (mis-spawned executor, correct `WORKTREE_PATH` input, wrong inherited ambient cwd). The check must inspect the ambient cwd as actually inherited.
- **Round 2**: the ambient cwd for a **correctly**-spawned role is normally an *ancestor* of `WORKTREE_PATH`, not `WORKTREE_PATH` itself or a descendant of it — every project's `worktree.base` config (e.g. this repo's `.concertino/worktrees`, helio's `.claude/worktrees`) nests worktrees under the driver session's own root, so the driver's ambient cwd is structurally never "under" any one ticket's `WORKTREE_PATH`. A check requiring `AMBIENT_PWD` to resolve under `WORKTREE_PATH` therefore `FAIL`s on **every normal spawn**, which is exactly the failure mode `ticket.md`'s Correction #1 already named and ruled out ("a bare pre-cd mismatch check would BLOCKER on essentially every spawn").

The two constraints are jointly satisfiable, but not via a bare "ambient must be under `WORKTREE_PATH`" predicate — the check needs to discriminate specifically on the incident's actual signature: **ambient resolves inside some *other* ticket's worktree**, not on whether ambient resolves inside *this* ticket's worktree at all (which a correct spawn need not satisfy).

## Goals / Non-Goals

**Goals:**
- Detect the actual incident signature: an agent whose ambient cwd resolves inside a *different* ticket's worktree than the `WORKTREE_PATH` it was instructed to work in.
- Do not BLOCKER a correctly-spawned role whose ambient cwd is, as expected, an ancestor of `WORKTREE_PATH` (the driver/orchestrator's own root) rather than `WORKTREE_PATH` itself.
- Make detection mechanical (script, non-zero exit) rather than relying on an agent noticing on its own.
- Cover every worktree-bound role (executor, evaluator, skeptic, auditor) uniformly via one canonical script.
- Close the "later relative invocation runs against the wrong tree" hazard **definitively** — not by arguing it can't happen, but by making every affected invocation immune to ambient cwd regardless of what `assert-cwd.sh` found.

**Non-Goals:**
- **This change does NOT fix the CON-139 reporting-channel gap.** CON-139 is about `ORCHESTRATOR_AGENT_REF` not being a structured, validated spawn input, causing a silent-fallback-to-`main` self-notify misdelivery — a different mechanism (message addressing) than this change's (cwd/worktree-collision detection). **Decision: left entirely to CON-139.** (This scope call itself was independently confirmed sound by both design-gate rounds against CON-139's actual ticket text; only the *rationale sentence* accompanying it kept needing correction as the mechanism changed — see Decision 3.)
- Not attempting to sandbox/jail the agent's filesystem access beyond the specific collision this ticket's incident describes.
- Not changing `start-servers.sh`'s existing port/cwd verification (CON-165) — unrelated code path.
- Not attempting to make a role's `cd` persist across Bash calls (impossible per the reproduced reset semantics) — the design works within that constraint.
- Not covering the orchestrator's own 18 bare `scripts/concertino/...` invocations — the orchestrator is not spawned into a worktree the way the four sub-roles are (it operates from the main checkout by design, and does not claim "all commands run inside `WORKTREE_PATH`" the way `core/roles/executor.md:20` etc. do), so it is not in scope for this ticket's AC.

## Decisions

### Decision 1: `assert-cwd.sh` detects cross-worktree collision, not cwd-equality
Contract:
```
assert-cwd.sh <AMBIENT_PWD> <WORKTREE_PATH> <BRANCH>
```
1. `WORKTREE_PATH` missing/not-a-directory → `FAIL worktree-missing: <path>`, exit 1. Otherwise resolve `WT=$(realpath "$WORKTREE_PATH")`.
2. Resolve `AMB=$(realpath "$AMBIENT_PWD")`. (`AMBIENT_PWD` is a real, just-captured `pwd -P` output — see Decision 3 — so this should always succeed; a failure here is `FAIL ambient-path-invalid`.)
3. Compute `BASE` exactly, from `BRANCH` (already an argument), rather than by a positional heuristic: `BASE="${WORKTREE_PATH%/$BRANCH}"` — grounded in `core/scripts/setup-worktree.sh:250`, which constructs `WORKTREE_PATH` literally as `"${REPO_ROOT}/${WORKTREE_BASE}/${BRANCH}"`, so stripping the trailing `/$BRANCH` recovers `${REPO_ROOT}/${WORKTREE_BASE}` exactly, regardless of how many path segments `BRANCH` itself contains (round 3 found a real 2-segment worktree on disk, `.claude/worktrees/task/matt-audit-repo`, that a 3-levels-up heuristic would get wrong). If `WORKTREE_PATH` does not end in `/$BRANCH` (should not happen given the construction above, but defensive), `BASE` is treated as empty (collision check below is then skipped — degrades to "no collision check possible," never a false BLOCKER).
4. **Collision check**: if `AMB` resolves under `BASE` (i.e. ambient is *somewhere* inside the worktrees tree at all) **and** `AMB` does **not** resolve under-or-equal to `WT` → `FAIL cwd-mismatch: ambient=<AMB> is inside a different worktree under <BASE> (expected under <WT>)`, exit 1. **This is the incident's actual signature**: landing inside a *different* ticket's worktree under the same base. **Boundary cases, disambiguated explicitly (round 3 CR #3):** `AMB == WT` (ambient is exactly `WORKTREE_PATH`, the post-mandated-`cd` steady state) → under-or-equal, tolerated, passes. `AMB == BASE` (ambient is the worktrees-base directory itself, e.g. someone `cd`'d to `.concertino/worktrees` without descending into any specific ticket) → tolerated, passes — it is under `BASE` but is not inside any *other* ticket's worktree, so it is not the incident signature; only a location strictly inside a sibling worktree fails.
   If `AMB` is **not** under `BASE` at all (the ordinary case — ambient is the driver/orchestrator's own root, an ancestor of every worktree, never itself inside the worktrees tree) → tolerated, no FAIL. This is what makes a normal spawn pass: the driver's ambient cwd is structurally outside `BASE` entirely, so it can never collide with any single ticket's `WORKTREE_PATH` by this check's definition.
5. **Branch check** (independent of the collision check — this verifies `WORKTREE_PATH` itself is the run's intended worktree, regardless of where ambient is): `cd "$WT"` (legitimate here — only used for this script's own `git` call, never to relocate the caller) and check `git_child rev-parse --abbrev-ref HEAD` (via `lib/git-child-env.sh`, CON-133 hermetic-git pattern) equals `BRANCH`. Mismatch → `FAIL branch-mismatch: found=<x> expected=<y>`, exit 1.
6. Success: `READY ambient=<AMB> branch=<BRANCH>`, exit 0.

Invoked via the absolute path `"$WORKTREE_PATH/scripts/concertino/assert-cwd.sh" "$(pwd -P)" "$WORKTREE_PATH" "$BRANCH"` — never a bare relative invocation, since locating the check itself must not depend on the very ambient-cwd correctness being verified (unchanged from rounds 1–2, both confirmed this sound).

Traced against both rounds' counterexamples:
- **Round 2's counterexample** (a correctly-spawned role, ambient = driver's own repo root, e.g. `/home/matt/Development/helio`, `WORKTREE_PATH` a descendant under `.claude/worktrees/...`): `BASE` = `.claude/worktrees`; ambient is NOT under `BASE` (it's an ancestor of `BASE`, not a descendant) → collision check tolerates it → proceeds to branch check on `WORKTREE_PATH` itself → `READY`. **Does not BLOCKER.**
- **The live incident** (executor spawned for lane 2, ambient = lane 1's `WORKTREE_PATH`, both under the same `.concertino/worktrees` base): `BASE` matches for both; ambient IS under `BASE` but NOT under lane 2's `WT` → `FAIL cwd-mismatch`. **BLOCKERs, correctly.**

### Decision 2: closing the "32 relative invocations" hazard by fixing the call sites, not by arguing they're safe
Round 1 raised, and round 2 confirmed the concern was never actually closed: a `READY` from Decision 1 does **not** imply `AMBIENT_PWD == WORKTREE_PATH` (a correct spawn's ambient is typically an *unrelated ancestor*, per Decision 1's collision-only check). So every bare, ambient-cwd-relative `scripts/concertino/<x>` invocation in the four worktree-bound role docs (mechanically re-enumerated round 3, via `grep -nE '^\s*`?scripts/concertino/[a-zA-Z0-9_-]*\.sh|then `scripts/concertino/[a-zA-Z0-9_-]*\.sh' core/roles/{executor,evaluator,skeptic,auditor}.md`: executor 1, evaluator 6, skeptic 6 — including `skeptic.md:93`/`:94`, the `start-servers.sh`/`assert-phase.sh` sites round 1's original count missed — auditor 3 — **16 total**; the orchestrator's own bare invocations are out of scope, see Non-Goals) would, on a correctly-passing spawn, resolve against whatever `scripts/concertino/` exists at the *ambient* location (the driver's own checkout) rather than the worktree's own copy — silently wrong in general (a different commit's rendered scripts, or simply the wrong tree for any worktree-relative argument alongside it), even though `assert-cwd.sh` itself returned `READY`.

This is fixed directly, not argued around: **every one of these 16 call sites is rewritten to be immune to ambient cwd**, either by prefixing with an explicit `cd "$WORKTREE_PATH" && ` in the same command (so the `cd` takes effect for that one compound call, which does not require it to persist across calls), or by using the same absolute-path form `"$WORKTREE_PATH/scripts/concertino/<x>"` Decision 1 already uses for `assert-cwd.sh` itself, for consistency. Once every such call site is rewritten, `assert-cwd.sh`'s `READY` genuinely does mean "safe to proceed" for the whole of the role's remaining session — not because the ambient baseline happens to be `WORKTREE_PATH`, but because nothing downstream depends on that anymore.

### Decision 3: detection is mechanical; response is a prompt-level BLOCKER-and-stop
The role's literal first action (before `## Resumability`/`## Evidence discipline`/`## Setup`, added as a new top-of-file section right after `## Input` in each of the four role docs) is: (a) capture ambient cwd via a standalone `pwd -P` — nothing else in that Bash call; (b) invoke `assert-cwd.sh` per Decision 1; (c) on `FAIL`, BLOCKER-and-stop — report the mismatch, perform no other read or write; (d) on `READY`, proceed normally.

**`ticket.md` AC #1 reconciliation.** The ticket's originally-stated AC #1 ("an unconditional `cd \"$WORKTREE_PATH\"` followed by a mechanical verification") is not implementable as literally written under the reproduced cwd-reset semantics — a `cd` inside the role's own first action would not survive to its second Bash call either (only a `cd` chained into the *same* compound command survives, which is exactly Decision 2's fix for the 16 call sites, not a standalone first action). `ticket.md` is updated to state the actually-implementable, actually-correct shape: capture-then-verify via `assert-cwd.sh`, plus the every-call-site immunity of Decision 2 — the combination that satisfies the AC's *intent* (no read/write happens against the wrong tree) without relying on an impossible persistence guarantee.

**CON-139 rationale, stated against what this mechanism now actually does (third and final time — this statement is now derived from Decision 1's traced behavior, not asserted against an intended one):** a role now BLOCKERs specifically when, and only when, its ambient cwd resolves inside a *different* ticket's worktree — exactly the live incident's signature — while a correct spawn's ordinary ancestor-relationship to `WORKTREE_PATH` is tolerated and proceeds normally. So: once this ships, the live incident (a role whose ambient cwd collides with another lane's worktree) is caught and BLOCKERs before any read or write; a normal, correctly-routed spawn is unaffected. The general reporting-channel gap CON-139 independently describes (any raised ESCALATION/BLOCKER's self-notify misdelivering to `main`) remains open regardless — fixing that addressing mechanism is out of scope here.

### Decision 4: no shared-block parameterization is needed
Unchanged from rounds 1–2 (round 2 confirmed sound, no further action needed): `lib/cli/render.js`'s `block(name, c, harness)` has no per-call-site argument channel, and since Decision 1 carries no `ROLE_LABEL`, the shared `cwdGuard` block's text is identical fixed prose in all four role docs (only `$WORKTREE_PATH`/`$BRANCH`, already common vocabulary in every role's Input section). Add a `cwdGuard` block to `lib/cli/render.js`, referenced via `{{block:cwdGuard}}` — mirrors the existing `docsExecutor`/`specReadNote` pattern.

### Decision 5: mutation-scoped tests using the values a real spawn actually produces
Four cases, each naming its killing mutant, with case 1 now using the value round 2 measured as the actual output of a correct spawn (not a hand-picked value that never occurs):
1. **Correct spawn — two sub-cases, both drawn from measured real spawns (round 3 CR #4, widened from a single case):**
   - **1a. Ambient is an ancestor of `WORKTREE_PATH` in the same repo** (a distinct, real, pre-existing directory that is a parent of `WORKTREE_PATH`, not itself under `BASE` — round 2's measured counterexample) → `READY`.
   - **1b. Ambient is an unrelated directory in a *different repository entirely*, not an ancestor of `WORKTREE_PATH` by any path relation** (round 3's own measured counterexample: ambient `/home/matt/Development/helio`, `WORKTREE_PATH` under a `concertino` worktree) → `READY`. Kills the mutant that tolerates only the ancestor relation (e.g. a prefix test against `WORKTREE_PATH` rather than the `BASE`-containment test this design actually specifies) — that mutant would pass 1a and wrongly fail 1b, so 1b is what proves the check is testing "not inside a sibling worktree," not "is an ancestor of mine."
2. **Misdirected spawn (mirrors the live incident exactly)**: `AMBIENT_PWD` is a genuinely different, real, pre-existing worktree *under the same base directory* as `WORKTREE_PATH`, on a different branch → `FAIL cwd-mismatch`. Kills the mutant that deletes the "ambient under BASE but not under WT" collision check.
3. **Ambient (== WORKTREE_PATH) correct, branch wrong**: `WORKTREE_PATH` itself checked out to a branch other than `BRANCH` → `FAIL branch-mismatch`. Kills the mutant that deletes/no-ops the branch check.
4. **`WORKTREE_PATH` itself missing** → `FAIL worktree-missing`. Kills a mutant that hardcodes `exit 0` / skips existence checks.
Case 1 and case 2 are now the two values a real deployment actually generates (driver root vs. another lane's worktree, both under/outside `BASE` respectively) and produce different, correct verdicts — the discriminating power round 2 found missing.

## Risks / Trade-offs

- **`BASE` derivation risk retired (round 3).** The earlier "three levels up" heuristic is replaced by the exact `${WORKTREE_PATH%/$BRANCH}` derivation (CR2 above), grounded directly in `setup-worktree.sh`'s own construction of `WORKTREE_PATH` rather than an assumed branch-segment convention — so this is no longer a convention-dependent risk. `BASE` unresolvable (malformed input) still degrades to "no collision check," never a false BLOCKER.
- **False BLOCKER on a legitimately relocated worktree still under the same base as another ticket's**: acceptable — existing BLOCKER → human escalation path handles it, same as rounds 1–2.
- **Depends on the reproduced cwd-reset/fixed-baseline semantics** — recorded, not assumed, per the original Context risk (unchanged).
- **Decision 2 grows this change's diff** (16 call sites across 4 role docs) beyond the original single-script-plus-wiring scope — accepted as necessary once round 2 established that arguing the hazard away doesn't hold; it is a small, mechanical, per-line fix.
- **Does not close CON-139**: explicitly accepted, per Decision 3's corrected rationale.
