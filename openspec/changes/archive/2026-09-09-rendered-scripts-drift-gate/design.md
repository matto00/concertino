## Context

`npm test` in this repo is `node --test` followed by a long sequence of `bash test/scripts/*.test.sh` invocations. The bash tests follow a settled house shape: `set -uo pipefail`, `NO_COLOR=1`, a `ROOT` resolved from `BASH_SOURCE`, `PASS`/`FAIL` counters with `ok`/`bad`/`check` helpers, scratch state in `mktemp -d` rather than in the checkout, and a non-zero exit when `FAIL` is non-zero. Critically, they resolve the script under test from `core/scripts/`, never from `scripts/concertino/` — which is why the test suite remains trustworthy evidence about core even while the rendered copies are stale. This change must preserve that property: a check about drift cannot itself depend on the possibly-drifted copy.

`concertino sync` writes two files into `scripts/concertino/` that have no `core/scripts/` source: `.concertino.env` and `speeds.json`, both rendered from `concertino.config.json` (`lib/cli/sync.js`). Every other file in that directory is a verbatim copy of the `core/scripts/` file of the same relative path, including the nested `lib/` subdirectory. `lib/cli/doctor.js`'s `checkArtifacts()` already relies on exactly that property, enumerating with `listFilesRecursive(core/scripts)` and byte-comparing — so the comparison semantics this change needs are already established in the codebase and are not being invented here.

Two files, `pricing-table.json` and `report-cost.sh`, exist in `core/scripts/` and are untracked-but-present in the main checkout's `scripts/concertino/`. The owner has not ruled on them and has instructed that they not be committed, deleted, moved, or rendered over. They are absent from the delivery worktree, since a worktree checks out tracked content only.

## Goals / Non-Goals

**Goals:**
- Fail routine verification when `core/scripts/**` and `scripts/concertino/**` disagree, with a message that names the paths and the remedy.
- Distinguish "went stale" from "never arrived", since they are different problems with the same remedy but different diagnostic weight.
- Clear today's drift so the gate is green on arrival.
- Keep the check itself independent of the rendered tree, so it is trustworthy evidence about core.

**Non-Goals:**
- Changing `concertino sync`, `concertino doctor`, or any core script's behaviour. `doctor`'s existing WARN stays exactly as it is; this change adds enforcement beside it rather than relocating it.
- Making the check run in consuming repos. It governs Concertino's own self-hosted copies. A consuming repo legitimately renders from an older installed Concertino and is not in breach.
- Auto-fixing the drift. The check reports; a human runs `concertino sync` and reviews the diff. An auto-fixing gate would make the render un-reviewable, which is the opposite of the stated remedy.
- Adding a git hook. This repo has no `.husky/` and none is introduced, so the commit-gate chain is untouched and no gate-chain isolation evidence is owed.

## Decisions

**Decision 1: a bash test in the existing suite, not a node test and not a new command.** `test/scripts/rendered-scripts-drift.test.sh`, registered in `package.json`'s `test` script. Rationale: the thing being compared is a directory of shell scripts; the house bash-test harness already has the enumeration and reporting idiom, and registering it in `npm test` is the single change that makes the gate routine rather than on-demand. Alternatives rejected: (a) a `node --test` file — no advantage, and it would sit apart from every other script-level check; (b) extending `concertino doctor` to exit non-zero — `doctor` is a diagnostic a human runs deliberately, and making it fail would change its contract for consuming repos, which are legitimately allowed to drift; (c) a CI-only workflow step — invisible locally, and this repo's own delivery runs verify with `npm test`.

**Decision 2: enumerate from `core/scripts/**`, never from the rendered directory.** The set of files to compare is `listFilesRecursive`-equivalent over `core/scripts/`, relative paths preserved, then each is looked up under `scripts/concertino/`. This makes `.concertino.env` and `speeds.json` out of scope structurally: they are never enumerated, so no exclusion list can rot around them. It also means a file deleted from core but left behind in the rendered tree is not reported — an accepted blind spot, called out under Risks.

**Decision 3: two failure classes, one remedy.** Content mismatch and missing counterpart are collected into separate lists and printed under separate headings, mirroring `checkArtifacts()`'s existing `differs`/`missing` split and its stated reasoning ("one file never arrived, the other arrived and was then changed underneath them"). Both point at `concertino sync`.

**Decision 4: the exemption list suppresses missing-counterpart only, and every entry carries a reason.** Implemented as a literal, commented table at the top of the test script, seeded with `pricing-table.json` and `report-cost.sh` and the reason "owner has not ruled — tracked by CON-173". Rationale: the alternative of ignoring missing counterparts wholesale would mean a newly-added core script is never caught, which is the same silent-failure class this ticket exists to close; and committing those two files is explicitly forbidden by the owner's standing instruction. Confining the exemption to the missing case means an exempt file that is later rendered is immediately held to byte-identity, so the exemption cannot become a licence to drift. A written reason alone would not make the list decay — a comment in a shell script sits inert indefinitely, which is this ticket's own silent-staleness failure reproduced one level up in the gate's configuration. So the decay mechanism is external: CON-173 tracks the owner ruling on those two files, every exemption entry cites it, and resolving CON-173 either way deletes both entries. The list is read from the built-in table plus an environment-supplied addendum, so a test can add a synthetic entry without editing the script under test.

**Decision 5: clear the drift by copying core over the rendered files, not by running `concertino sync` in the worktree.** `concertino sync` in the delivery worktree would also render `pricing-table.json` and `report-cost.sh` into `scripts/concertino/`, and committing them would land on `main` through this PR — exactly what the owner instructed against. A direct copy of the four stale files reproduces byte-for-byte what a sync would have written for those files (they are verbatim copies by Decision 2's own premise) while leaving the two unruled files absent, which the exemption list then accounts for. The copy must be verified by the gate itself, not asserted.

**Decision 7: mutation evidence must never write to an owner-protected path.** Demonstrating that an exemption cannot suppress a content mismatch is done with a synthetic exemption entry over an ordinary rendered file, not by materialising `report-cost.sh`. Those two files are absent in the delivery worktree but present in the main checkout, whose path prefix contains the worktree, so a wrong working directory would delete exactly what the owner forbade. The property under test is identical either way; only the exposure differs.

**Decision 8: assert the rendered `.sh` is executable; do NOT compare the two modes.** `lib/cli/emit.js:450` forces every rendered `.sh` to `0o755` on copy, regardless of the core file's own mode — the script copy goes through `copyAssets()`, not through `sync.js`'s `write()`. Mode equality is therefore the wrong property: `core/scripts/lib/git-child-env.sh` is committed at `100644` while its render is committed at `100755` with an identical blob, so an equality gate would be red on arrival on a file this change does not otherwise touch, and its printed remedy (`concertino sync`) would recreate the mismatch on every run — an unclearable red. The property the renderer actually establishes is "every rendered `.sh` is executable", so that is what the gate asserts, independent of core's mode. This also keeps the change inside its Non-Goals: comparing modes would require altering `copyAssets`' unconditional chmod, which is a `concertino sync` behaviour change.

**Decision 6: the test resolves both trees from the repo root and compares the working tree, not git object content.** Consistent with every other test in the suite and with `doctor`. It means the gate is about what is on disk, which is what actually guards a run.

## Risks / Trade-offs

- **A core file deleted without deleting its render is not caught** (Decision 2). Accepted: the harm of a leftover rendered script is far smaller than the harm of a stale one, and closing it would require enumerating the rendered directory, which re-introduces the `.concertino.env` exclusion-list problem this design deliberately avoids.
- **The exemption list is a hole by construction.** Mitigated by confining it to the missing case and by tracking the open question in CON-173 rather than in a comment. Either resolution of CON-173 — render and commit the two files, or remove them from core — deletes both entries. Until CON-173 is resolved the exemption is indefinite, and this design does not pretend otherwise.
- **The environment-supplied exemption addendum is a new escape hatch.** Any caller setting that variable can suppress missing-counterpart failures for arbitrary paths. It exists so the exemption mechanism can be tested without editing the script under test, it cannot suppress a content mismatch, and nothing in normal use sets it — but it is a real widening of the gate's configurable surface and is recorded here rather than left implicit.
- **The gate is only as good as its mutation evidence.** A gate that passes against a clean tree proves nothing. The tasks therefore require demonstrating a red run for both failure classes, and the delivery must not rely on the delivery run itself being green as evidence — this run is guarded by the stale rendered copy, so only the suite's core-targeting tests are evidence about core.
- **Fixing the drift changes the behaviour of the rendered guards mid-flight.** After this merges, subsequent runs are guarded by the current `squash-branch.sh`, including its stricter index/worktree divergence refusal. That is the intended outcome, but it may surface refusals that the stale copy silently permitted. This is a correctness improvement presenting as new friction, not a regression.
