# CON-172: The rendered self-hosted scripts/concertino/ copies must not diverge from core/scripts/

## Description

Concertino self-hosts: it delivers its own tickets using the rendered scripts under `scripts/concertino/`, generated by `concertino sync` from `core/scripts/`. Those rendered copies are tracked in git. The obligation is that the rendered self-hosted copy must not diverge from core — a Concertino run must be guarded by the guards Concertino currently defines, not by a snapshot of what they used to be. That obligation is currently unmet.

The failure is silent in both directions. A stale rendered copy does not error; it enforces an older contract. And because `concertino.config.json` sets `cleanup.skipSync: true` in consuming repos, nothing auto-renders. The drift is only ever discovered by someone diffing the two trees by hand.

The convention flipped after CON-121 (`7008104` is the last commit that re-rendered alongside a core change) and nobody noticed. The last deliberate catch-up was `c203d27` (a hand-fix with no core change), which is exactly why it recurred.

## Acceptance criteria

1. A structural check fails when a file under `core/scripts/**` disagrees with its rendered `scripts/concertino/**` counterpart, and runs as part of the repo's own routine verification (the existing `npm test` suite) rather than only in an on-demand command.
2. The check is failable by mutation: mutating either copy makes it fail, and this is demonstrated by evidence, not asserted.
3. The check's failure message states the remedy — run `concertino sync` and commit the result as its own reviewable diff — and does not invite a hand-edit of the render target.
4. The check is not a naive byte-for-byte comparison of the whole tree: files with no `core/scripts/` counterpart (`.concertino.env`, `speeds.json`) are out of scope by construction.
5. The drift that exists today is actually fixed in this same change, so the check is green on arrival rather than red.
6. `scripts/concertino/pricing-table.json` and `scripts/concertino/report-cost.sh` are left untouched: not deleted, moved, committed, or rendered over.

## Recorded autonomous decision: the two unruled files

`core/scripts/pricing-table.json` and `core/scripts/report-cost.sh` have no tracked counterpart under `scripts/concertino/`. A drift check that treats "missing rendered counterpart" as a failure would therefore be red on arrival unless this change commits them — but the owner has explicitly not ruled on those two files and instructed that they not be committed. A check that ignores missing counterparts entirely is the worse option: a newly-added core script would then never be caught, which is the same silent-failure class this ticket exists to close.

Decision (owner asleep; recorded here rather than raised as a blocking escalation, per the run's escalation policy): the check treats a missing rendered counterpart as a failure, but honours a narrow, in-repo exemption list in which every entry must carry a written reason. It is seeded with exactly those two files, reason "owner has not ruled — tracked by CON-173". The exemption is visible, decays loudly, and does not weaken content-drift detection for any file that is rendered. Nothing about the two files in the main checkout is deleted, moved, committed, or rendered over by this change.
