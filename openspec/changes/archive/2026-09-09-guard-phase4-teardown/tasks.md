## 1. Script-owned auditor lease (Signal A — load-bearing)

- [x] 1.1 Add a shared helper under `core/scripts/lib/` exposing acquire / release / query for the lease at `.concertino/runs/<TICKET_ID>/locks/auditor.lease`, so `check-merge-readiness.sh`, `emit-event.sh` and `cleanup.sh` cannot drift apart on path, format, or root resolution. **The helper canonicalises the ticket id** (identically on acquire and release — `check-merge-readiness.sh` uses it raw while `emit-event.sh:292` uppercases, so an uncanonicalised key strands the run) and **resolves the run root itself**, via the same `git rev-parse --git-common-dir` path both writers already use (`check-merge-readiness.sh:138`, `emit-event.sh:96`) — callers must not pass a root in, and `cleanup.sh` must not use its own `REPO_ROOT` (`:129`, which is `--show-toplevel` relative to cwd and can disagree). Lease content records the acquiring script, the ticket, **the absolute `WORKTREE_PATH`**, **the acquiring pid**, and an ISO timestamp.
- [x] 1.2 In `core/scripts/check-merge-readiness.sh`, acquire the lease **after** argument and ticket-shape validation (`:122-123` rejects a malformed `TICKET_ID`, and `emit-event.sh:284` structurally refuses to release under one) but **before** any substantive readiness check — so a `FAIL` from a real check still leaves the lease held for the auditor's remaining lifetime, while no lease is ever created under a key the release path cannot address. Acquisition must be idempotent (a re-run must not error).
- [x] 1.3 In `core/scripts/emit-event.sh`, release the lease **on recognition** of a `verdict` invocation with `role=auditor`, for every verdict value — not downstream of the event write, and regardless of whether that write succeeds or is skipped by one of the script's early-exit / validation paths. Release must be idempotent and must never abort or fail the call, consistent with the existing "a lost event never fails the run" posture.
- [x] 1.3a Update `emit-event.sh`'s header comment block (`:5-53`), which currently documents the script as pure, side-effect-free telemetry, to document the lease release. An undocumented semantic side effect there is how this guard gets refactored away later by someone reasonably trusting the docs.
- [x] 1.4 Confirm no other caller of `check-merge-readiness.sh` or `emit-event.sh verdict` exists that would take or release a lease unintentionally. Record the **exact grep patterns run** alongside their zero-hit results — a zero-hit grep is evidence only if the pattern is shown.

## 2. Teardown guard in `cleanup.sh`

- [x] 2.1 Add `--force-teardown` parsing per design.md Decision 4: consumed only *after* the existing `--phase4` / `CONCERTINO_PHASE4=1` opt-in check, which is otherwise unchanged. Both legal entry forms must accept it. After flag consumption, an argument still beginning with `--` must fail with a usage error rather than binding as `WORKTREE_PATH`. Document the flag in the usage header.
- [x] 2.2 Insert both checks after the dev/backend port kills and strictly before the worktree-removal block, so a refusal leaves the run fully retryable (no branch deleted, no fast-forward attempted).
- [x] 2.3 Lease check: scan `<run-root>/.concertino/runs/*/locks/auditor.lease` for any lease whose **recorded worktree path** matches the worktree about to be destroyed — do not key the lookup on `T` (`cleanup.sh:149` infers `T` from a basename when the optional 4th argument is omitted, which for a non-conforming branch name is not a ticket id and would make the check a silent no-op). If one is held, refuse immediately — no settle window — naming the lease, its pid, and its timestamp. If the run root cannot be resolved at all, **fail closed**: refuse and say the lease could not be checked.
- [x] 2.4 Process probe: implement `worktree_holders()` enumerating pids whose `/proc/<pid>/cwd` resolves to `WORKTREE_PATH` or beneath it. Exclusion set is the **literal ancestor pid chain only** (self → PPid → … → 1), never siblings or other descendants. Tolerate pids vanishing mid-scan under `set -e`. Where `/proc` is unavailable, report no holders.
- [x] 2.5 Settle window for the process probe only: re-probe every 250 ms up to a 3 s bound; refuse only if the holder set is non-empty when the bound elapses. Never wait past the bound. **The bound is a wall-clock deadline captured once (`now_ms() + 3000`), never a running sum of `sleep` durations** — a sum-of-sleeps undercounts by the probe's own cost, which grows with machine pid count/load (evaluation cycle 1 CR-1: measured ~9.5s/~10.9s idle/under-load for a documented 3s bound before this correction). `worktree_holders` batches its `/proc/<pid>/cwd` resolution into one `readlink` call instead of forking per pid, to keep the probe itself cheap.
- [x] 2.6 On refusal, exit via the existing `fail()` path so exactly one `RESULT` line is printed with the worktree reported as not removed; include the lease and/or each holder's pid and command line in the output.
- [x] 2.7 Under `--force-teardown`, print the lease and holders being overridden, then proceed. Verify no environment variable or default can reach this path.
