### Change Requests

1. **The cycle-2 `readlink` batching never engages on a real Linux host, and `design.md`'s rationale for it is measurably false.** `core/scripts/cleanup.sh` `worktree_holders` batches all `/proc/<pid>/cwd` into one `readlink` and falls back to the per-pid loop whenever the output line count differs from the argument count. `readlink` silently omits a line not only for a pid that *vanished*, but for any `/proc/<pid>/cwd` it cannot read — which includes every root-owned process. Measured on this machine, reproduced twice: `argc=581, outlines=252`. The counts therefore mismatch on essentially every scan, so the batched fast path is dead and the fallback loop runs every time. `design.md` Decision 3 states the batching "gives the wall-clock deadline more headroom against pid-count growth" and that it "fixes the class of defect directly" — neither is true as shipped; the wall-clock deadline alone is what fixes CR-1's defect. Resolve by either (a) deleting the batched path and its mismatch-fallback, keeping only the per-pid loop (my preference — it removes net complexity from a script that now runs on every delivery, at a measured cost of 0.32 s per scan against a 3 s bound), or (b) making the batch alignment robust to unreadable entries and demonstrating with a measurement that it engages. Either way, correct the Decision 3 paragraph so it no longer attributes headroom to a path that does not run. Same edit in the rendered `scripts/concertino/cleanup.sh` (direct copy, no `concertino sync`).

2. **Two residual "structurally impossible"-class overclaims survive in the two most-quoted lines of the artifacts.** (a) `openspec/changes/guard-phase4-teardown/design.md`, Goals bullet 1: "Make it structurally impossible for `cleanup.sh --phase4` to destroy a worktree that a live process is using." This directly contradicts the same document's Honest scope statement, which says the earlier draft "did make that claim and it was not true" and that Signal B is best-effort and Linux-only. (b) `openspec/changes/guard-phase4-teardown/specs/phase4-teardown-safety/spec.md:3` (Purpose): "Guarantee mechanically that Phase-4 teardown never destroys a worktree while **an agent** is still working inside it." Signal A brackets the **auditor** only; any other agent gets no lease, and the spec's own requirement text three paragraphs down says so. The Purpose line is the sentence that survives into `openspec/specs/` at archive, so it is the one most likely to be read out of context later. Rewrite both to the scope the requirements actually state — auditor-bracketed guarantee plus a best-effort complementary probe.

### Non-blocking notes

- The lease is matched on the exact recorded worktree string, with no normalisation on either side. Today both call sites receive the same `WORKTREE_PATH` variable from the orchestrator, so this holds; but a trailing slash or a relative path at one call site would silently fail **open** (degrading to today's behaviour, not to a new failure). A `realpath`/normalisation pass inside `lease_acquire` and `lease_find_by_worktree` would close it cheaply. Not blocking — the failure direction is the safe one and no current call site can trigger it.
- `pid_dir` in `worktree_holders` is not declared `local`; it leaks into the caller's scope. Harmless today, worth tidying alongside CR-1.
- An abandoned run that ran `check-merge-readiness.sh` and never emitted an auditor verdict leaves a lease on disk indefinitely. Harmless (matching is worktree-path-scoped, and a re-run re-acquires), but a `doctor` check for stale leases would be a reasonable follow-up.
- `design.md`'s "The recovered CON-163 report records `Condition 1-3 (check-merge-readiness.sh) — PASS`" leans on a report the same document correctly declines to treat as primary evidence. The conclusion is independently supported — `auditor.md` makes the script a hard precondition of merging — so this is a citation nit, not a reasoning defect.
