- `core/scripts/set-ticket-state.sh` — after the existing temp-file+rename write succeeds, commits the rewritten ticket file by itself (pathspec-limited to `$ID.md`, never `$FILE` or `-a`/`add -A`) when `<tickets-dir>` is inside a git working tree, then makes one best-effort, non-forced `git push` of that commit to the checked-out branch's remote (`CONCERTINO_BASE_REMOTE`, defaulting to `origin`, sourcing `.concertino.env` the same way `cleanup.sh` does). Both steps are silently skipped when `<tickets-dir>` isn't a git working tree or `HEAD` is detached (push only). Neither failure mode changes the script's `OK <id> <state>` / exit 0 contract — only stderr notes.
- `test/scripts/set-ticket-state.test.sh` — new test block seeding a real git repo (`seed_git`/`write_ticket_file` helpers): commit-only-the-one-file, unrelated-dirty-file-untouched, push-succeeds, push-rejected (with a stderr-note assertion), detached-HEAD (commit but no push), and the required relative-`<tickets-dir>` regression test (design.md Decision 2) that mirrors the orchestrator's actual `cwd`+relative-arg call shape. All pre-existing `mktemp -d`-without-`git init` cases are unmodified and now exercise the "not a git working tree" no-op path.
- `docs/config-reference.md` — rewrote the "Status write-back leaves the main checkout dirty" section (retitled "Status write-back commits (and best-effort pushes) each transition") to describe the new commit/push behavior and explicitly document the residual push-protected-branch case where `cleanup.sh`'s existing `diverged` escalation can still occur.
