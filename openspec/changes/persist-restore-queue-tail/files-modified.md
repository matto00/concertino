# Files modified

- `lib/ui/queue-cache.js` — new module: reads/writes `.concertino/cache/queue.json` (temp-file + rename, malformed/missing reads as `null`), and `isStale()` for the 24h restore bound. Mirrors `lib/ui/cache.js`'s pattern; reuses `cache.cacheDir()`.
- `lib/ui/queue.js` — `createQueue()` now sets `confirmed: true` explicitly; `tick()` carries `confirmed: true` (and `restoredFrom`, if present) forward on its returned queue; added `shouldTick()` (the pure guard watch.js's poll loop uses), `reconcileRestored()` (filters a persisted record's `pending`/`inFlight` through the existing `isRunLive` predicate against a fleet snapshot), and `createRestoredQueue()` (builds the paused/unconfirmed restored queue object, or `null` when reconciliation leaves nothing to restore). Updated the file-header comment to describe the new persist/restore flow.
- `lib/ui/watch.js` — requires `crypto` and `queue-cache`; added a one-off startup `reduce()` pass that reads `queue-cache`, applies the staleness bound, and restores a queue via `queue.createRestoredQueue()` before the poll loop starts; the `draw()` tick call site now writes the queue file on every non-idle tick and clears it on idle, gated by `queue.shouldTick()` so an unconfirmed restored queue never ticks; `confirm-launch` now mints a `queueSessionId` (`crypto.randomUUID()`); added the `confirm-restored-queue` action handler; rewrote the `queueState`/added the `queueSessionId` doc comments to describe the new persisted/restore design instead of the old in-memory-only trade.
- `lib/ui/screens/fleet.js` — added `CONFIRM_RESTORED_QUEUE_KEY` ('c'); `renderFleet()` now renders a "resumed from a previous session — press c to continue" footer line whenever `queueState.confirmed === false` (covers the pending-empty/inFlight-only edge case too); `handleKey()` dispatches `confirm-restored-queue` for that key when such a queue is present; exported `CONFIRM_RESTORED_QUEUE_KEY`.
- `test/queue-cache.test.js` — new: round-trip, cold/malformed-read-as-empty, shape validation, staleness bound, `clear()`, and a persistence-shape assertion that a written record never carries ticket titles/descriptions.
- `test/queue.test.js` — added: `confirmed` is always explicit on `createQueue`/`tick` output; `shouldTick()`; `reconcileRestored()` (pending drop/survive, in-flight keep/free); `createRestoredQueue()` (reconciled build, `maxConcurrent:1` slot-occupancy safety, empty-reconciliation returns `null`, inFlight-only restore); confirming a restored queue never mutates pending/inFlight.
- `test/fleet.test.js` — added: the resume affordance renders (and names the confirm key) for an unconfirmed restored queue, including the inFlight-only edge case; it does not render for a confirmed or pre-CON-29-shaped queue; the confirm key dispatches `confirm-restored-queue` only when such a queue is present.
